# BloodyClick 固件兼容配置

这个目录是 BloodyClick 的兼容数据更新源，位于 `aorigami/Bloodless` 的 `bloodyclick-compat` 分支。原参考项目的 `main` 分支不受影响。

## 用户使用

新版 BloodyClick 启动后先使用内置或缓存的配置连接鼠标，后台检查本目录的 `catalog.json`。正常联网时每 6 小时检查一次，也可点击“检查兼容更新”。检查失败 15 分钟后重试；检测到未适配固件时立即检查，此后每 5 分钟重试。

程序空闲时每 5 秒重新查询设备固件；USB 重插或固件变化后自动重新连接。已发布且通过校验的新配置在按键释放、面板临时隐藏结束后应用，无需重新安装主程序。下载不占用按键发送线程。

EXE 旁的 `BloodyClick.compat.json` 保存当前配置，`BloodyClick.compat.previous.json` 保存上一份。断网、下载损坏或签名不符时，保留已有配置；本地文件损坏时依次使用可验证的备用缓存和内置配置。这个目录需要允许当前用户写入，才能保存更新。

自动更新的是**兼容配置**，不是鼠标固件，也不会上传或改写板载宏。更新请求不包含鼠标序列号、宏或其他设备数据。

## 当前适配

仅匹配 W95 Ultra5 的 VID `09DA`、PID `3FA0`、接口 `MI_02&Col05`、Usage `FF33:0B37` 和 64 字节 Feature Report。

| 固件签名 | 可用逻辑键 | 释放方式 |
| --- | --- | --- |
| `37 0B 11` | 1–24 | 原按键掩码 |
| `37 0B 34` | 1–16 | 全零掩码 |

所有主页实体按键均包含在上述范围内。`37 0B 34` 的 17–24 位会触发滚轮或厂商快捷功能，未开放。

## 适配边界

配置可以更新精确固件签名、状态/设置地址、按键映射、按键数量、释放方式和火力模式基数。新固件仍使用现有 `w95-hid-v1` 协议时，维护者验证并发布一份新配置，客户端就能自动获得适配，无需重新编译 EXE。

程序不会猜测未知固件的地址，也不会通过网络自行生成适配。更新源尚无该版本时，显示具体固件并等待配置；如果 USB 协议、型号接口或指令语义发生现有引擎无法表达的变化，仍需更新主程序。应在原引擎配置中保留已支持条目；新的不兼容引擎须使用独立版本的配置源。

## 维护和发布

`catalog.source.json` 是可读源文件，`catalog.json` 是客户端接受的签名封装。客户端固定发布者公钥，使用 Ed25519 校验签名；只接收比当前版本更新的配置，拒绝同版本改写、降级以及超出协议约束的字段。客户端不下载执行脚本。

在 BloodyClick 源码目录中维护：

1. 对新固件完成接口、地址、动作及释放的验证；在 `compat/catalog.source.json` 中追加精确签名，保留旧固件条目。
2. 增加全局 `revision`（当前使用日期加序号），填写发布日期。禁止在同一 revision 下修改内容。
3. 使用本机签名工具生成发布文件：

   ```powershell
   python tools/sign_compat.py --private-key .compat-private/publisher.key
   python -m unittest discover -s tests -q
   ```

4. 将 `compat/catalog.json`、`compat/catalog.source.json` 和相应说明提交到 `bloodyclick-compat` 分支。可用 `python -m bloodyclick --check-updates` 验证实际下载，再检查设备状态。

签名私钥仅保存在维护者电脑的 `.compat-private/publisher.key`，不在本分支或 EXE 内。请单独备份；不要提交、分享或把它放在更新服务器上。没有此私钥无法为现有客户端发布新配置，丢失或更换时需要更新主程序内置的发布者公钥。

更新地址依次为 GitHub Raw 和 GitHub Contents API，均为 HTTPS。客户端没有登录令牌，普通用户无需登录 GitHub。
